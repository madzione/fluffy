# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"fluffy" — a work-in-progress CLI that integrates Go code into any Flutter/Dart project. Go is compiled to a C shared/static library and called over `dart:ffi` on native targets, or compiled to WebAssembly and called through JS globals on web.

The repo root is the `fluffy` Go CLI (module `github.com/madzione/fluffy`, `package main` directly in the root). `examples/` holds Flutter projects created with `fluffy create` (each with its own `golang/go.mod`, so `go test ./...` in the root skips them):

- `examples/todo/` — the service workflow: the plain-Go package `golang/todo/` (no fluffy import, `Service` with a `Watch` stream, `//fluffy:dart` interface `UI`, `store.go` JSON file natively / `store_js.go` localStorage) bound through `fluffy.Start`/`Bind("todo", ...)` in `golang/main.go`, with a widget test against `Bridge.fake()` and an integration test against the real Go library (`XDG_CONFIG_HOME=$(mktemp -d) fvm flutter test integration_test -d linux`).
- `examples/todo_module/` — the same app with the service as its own module `example.com/todo` in `examples/todo_module/todo/`, required in `golang/go.mod` with a local `replace`.
- `examples/roundtrip/` — conformance checks and fluffy's end-to-end regression test: `golang/sample/` (`Everything`, a field per mapped type, `Want()`, `Diff`, `testdata/want.json` shared with the Dart unit test) and `golang/api.go` (exports + `//fluffy:dart Host`); `lib/checks.dart` holds the checks, used by the app and `integration_test/app_test.dart`. Checks compare on the receiving side; a check with a `note` pins a known limitation. Run on Linux (`fvm flutter test integration_test -d linux`) and web (`fluffy lib web`, chromedriver on 4444, `flutter drive --release ... -d web-server`) after changing the templates or the generator.
- `examples/mandelbrot/` — heavy work: `golang/fractal/` renders bands in worker goroutines streamed as `Tile`s, cancelled with the Dart subscription (`yield_js.go` waits for a MessageChannel message between tiles so Go wasm hands the browser's main thread back; `time.Sleep` would cost 4 ms per tile); `golang/bench/` + `lib/bench.dart` measure bridge latency/throughput (results in `build/integration_response_data.json` with flutter drive). On Linux a Go→Dart message waits ~1 ms for the embedder's main thread (same as an isolate message) unless it comes back through the sync wait of `FluffySend`.

`skills/fluffy/SKILL.md` is the agent skill for users of fluffy (installation in the README). Update it when commands, generator rules or user-facing behavior change.

`fluffy` is installed with `go install .` into `~/go/bin` (fish: `fish_add_path ~/go/bin`). Inside an example prefer `fvm flutter ...` when it has a `.fvmrc`.

## Commands

From the repo root:

```sh
go build -o fluffy .
go install .                                   # the build hooks call fluffy from PATH
go test ./...                                  # includes vetting the Go template natively and for js/wasm and running the layer tests
go test . -run TestXcodeHook                   # single test
go test . -run TestGenerate -update            # rewrite the generator golden files in testdata/generate/
(cd _templates/layer/golang && go test -race .)   # only the message layer tests (TestGoTemplate runs them, ./... skips the _ dir)
```

In an example (e.g. `examples/todo/`): `fluffy update` after changing the templates, `fluffy run -d linux`, `fvm flutter test`.

## Architecture

### fluffy CLI
- Commands: `create` (flutter create + init; with fvm on PATH it creates via `fvm spawn <version>` and pins the new project by writing its own `.fvmrc` before `fvm use`, since fvm otherwise pins the nearest parent `.fvmrc`. Version order: `--fvm <version>`, `fvm api project` pin of cwd or a parent, fvm global symlink), `init` (scaffold + hooks + `flutter pub add ffi`), `update` (sync the communication layer + re-apply hooks, needs `golang/go.mod`), `generate [--check|--watch]` (see below), `lib <linux|windows|macos|android|ios|web>` (builds **only** the Go library; `--ndk-version`, `--strip`; when `go build` fails and `golang/fluffy_api.go` is stale it rewrites only that file and retries), `build <target>` (generates, builds web wasm for `web`, then `flutter build`; a call from an older hook — android, lib flags like `-o`/`--arch`/`--sdk`, or `FLUFFY_IN_FLUTTER` set by fluffy for its flutter subprocesses — is treated as `lib`), `run` (generates, builds web wasm when the device may be a browser, then `flutter run`). Unknown commands pass through to `flutter` without generating; `fvm flutter` is used when the project has `.fvmrc`. `init` and `update` also generate (failures only warn).
- `init` scaffolds from embedded `_templates/` (the `_` prefix keeps the Go tool from compiling the template as part of the CLI module). User-owned templates (`_templates/golang` → `golang/`, `_templates/dart` → `lib/golang/`) never overwrite existing files. The communication layer (`_templates/layer/golang` → `golang/fluffy/`, `_templates/layer/dart` → `lib/golang/src/`) is owned by fluffy: `syncLayer` (run by `init` and `update`) overwrites changed files and deletes files no longer in the templates. It skips `_test.go` files: the layer tests (`_templates/layer/golang/fluffy_test.go`) stay in the fluffy repo. `create` also writes `_templates/app/` over Flutter's counter `lib/main.dart` and `test/widget_test.dart` (demo app using `add`, `hello`, `clock`).
- Message layer (templates): Dart and Go exchange JSON envelopes `{type: emit|request|response|error, id, channel, data, error, bin}` on named channels, symmetric in both directions. On the wire each is a frame (`uint32` JSON length, `uint32` blob count, JSON, blobs with `uint32` lengths; `bridge.go` and `frame.dart`): byte slices travel as blobs where the receiver puts them back cheaply, `bin` holds their paths in `data` (`codec.go`: a top-level `[]byte`, or a `[]byte` field of a top-level struct without embedded fields/marshal methods/name clashes; Dart sends `Uint8List` at the data, list elements and their map values; Go decodes other paths by splicing base64 back in). The generated `toJson` stays base64, only top-level Dart arguments/results are sent raw. Sending is the emitter (`Emit`/`Request[R]` in Go, `emitter.emit`/`emitter.request<T>` in Dart), incoming messages go to handlers registered on the receiver (`On[T]`/`Handle[T,R]` in Go, `receiver.on<T>` stream / `receiver.handle` in Dart).
  - Streams: Dart `emitter.subscribe` sends `subscribe` (id, channel, data), Go answers `next`… then `done` or `error`, Dart `cancel` cancels the Go ctx. Backpressure: Dart sends `credit` `[count, bytes]` for values it added to an unpaused controller (microtask natively, `Timer.run` on the web so a fast stream can't starve the browser in microtasks); Go's `serve` waits while 1024 values / 8 MiB are unacknowledged. On reconnect (hot restart) Go cancels all subscriptions, drops answers/stream messages for the old connection (`out.conn` counter, captured at `deliver`) and fails its pending `Request`s to the old isolate. `receiver.stream` serves subscriptions on the Dart side, only for `Bridge.fake()`.
  - Go: `golang/fluffy/` package (template source `_templates/layer/golang/`) (`bridge.go` protocol + queue until Dart connects + `Start`, `emitter.go`, `receiver.go` with `Handle`/`On`/`Bind`/`Export`/streams; handlers run in goroutines, panics become error answers). `Start(fn)` runs once on the first connect (in a goroutine, never blocking the transport), every handler waits for it and gets its error if it failed. `Bind[T](ns, impl)` / `Export(channel, fn)` register functions by reflection as `<ns>.<Method>`: optional `context.Context` first, positional args as a JSON array, results nothing/`R`/`error`/`(R, error)`, a `<-chan T` result is a stream. Unsupported methods are skipped. Outbox and doorbell: `post` appends frames to `out` and rings Dart once (`rung`); Dart takes everything in one call. Incoming frames (`deliver`) are decoded on Dart's thread when small (≤64 KiB JSON, ≤4 MiB), else by an ordered reader goroutine; frames of an older connection are dropped. Transports: `transport_cgo.go` (`!js`, exports `FluffyConnect(ring)`/`FluffyAlloc`/`FluffySend`/`FluffyTake`/`FluffyFreeFunction`; `FluffySend` takes ownership of a `FluffyAlloc` buffer and, for request/subscribe, `await`s the first answer up to `syncWait` (250 µs) and returns 1 so Dart takes it in a microtask; channels that miss it go to `slow` until answered in time; Dart wraps the taken buffer with `asTypedList(finalizer: free)` and blobs ≥64 KiB stay views of it) and `transport_js.go` (`js && wasm`, `globalThis.golang.connect(receive, ring)/send/take`: JS→Go calls cost ~8 µs, Go→JS ~0.2 µs, so `connectPush` pushes the first message of a run of Go directly and only later ones go through the outbox; `resumePush` on every send; `Serve` blocks; `fluffy.Yield` uses a MessageChannel). User code: `golang/api.go` has `//fluffy:export` functions (demo `Add`, `Hello`, `Clock`), `golang/main.go` calls `fluffy.Serve()` and has `//go:generate fluffy generate`. Setup belongs in `fluffy.Start` (native `main` never runs). Both are `.tmpl` because they import `<package>/golang/fluffy`.
  - Dart: `lib/golang/golang.dart` exports `api.dart` (user code, re-exports the generated `api.g.dart`) and `src/bridge.dart` (library with parts `emitter.dart`/`receiver.dart`; `Bridge.fake()` gives widget tests an in-memory Go side). `src/` (template source `_templates/layer/dart/`): `transport.dart` exports `frame.dart` (`Send`, frame writing) and conditionally `transport_ffi.dart` / `transport_web.dart` (`connectGo`). The layer no longer imports `package:ffi`, `init` still adds it.
- `generate` (`analyze.go`, `dart.go`, `gogen.go`, `generate.go`): loads `golang/` with `go/packages` as `GOOS=js GOARCH=wasm` (no cgo needed) with `golang/fluffy_api.go` overlaid by an empty file, so a stale generated file never breaks it and `undefined: new<X>` errors for its own constructors are ignored. Pass 1 walks the import graph, pass 2 type-checks from source only packages of the user's modules (main module, `go.work`, local `replace`); the rest comes from export data. It finds calls of `fluffy.Handle/On/Emit/Request/Bind/Export` (constant channels only, others warn) and `//fluffy:export` funcs / `//fluffy:dart` interfaces, reports conflicts (channel twice, different types, Dart name clashes), and writes `lib/golang/api.g.dart` (top-level functions, a `Go<Ns>` class per channel prefix `ns.` reached via `golang.<ns>`, `abstract class` + static `register` per `//fluffy:dart` interface, a class per Go struct following encoding/json rules) and `golang/fluffy_api.go` (`fluffy.Export` registrations + `new<Class>()` implementations of the interfaces; removed when empty). Channels: `<Func>` in golang/, `<pkg>.<Func>` elsewhere, `<ns>.<Method>` for Bind, `<Iface>`/`<pkg>.<Iface>` + `.<Method>` for interfaces. Dart member, field and parameter names avoid `dartShadowed` (`int`, `bool`, `emitter`, `jsonEncode`, … get a `_` suffix), and `toJson` leaves out null optional fields (omitempty/omitzero or behind an embedded pointer, which Go would otherwise allocate). Both files are owned by fluffy. Golden files: `testdata/generate/` (fixture with a local `replace` module in `todo/`); the golden Dart is not compiled by the tests, check it with `dart analyze` in an example when the generator changes.
- Library names: `libgolang.so` (Linux, Android), `golang.dll`, `libgolang.dylib` (in the app's `Contents/Frameworks`), static `libgolang.a` on iOS (`DynamicLibrary.process()`), `web/golang.wasm` + `web/wasm_exec.js`.
- Hooks (`hooks.go`) all call back into `fluffy lib`, so `fluffy` must be on PATH at build time: CMake custom target (Linux/Windows, `--arch` from `FLUTTER_TARGET_PLATFORM`), Gradle `preBuild` Exec task writing to `android/app/src/main/jniLibs` (`--arch` from `-Ptarget-platform`, `--ndk-version` from `android.ndkVersion`; NDK found via env or `local.properties`), a first-position shell script build phase in `Runner.xcodeproj` (fixed object ID `F1FF1E000000000000000001`) plus `-force_load` in `ios/Flutter/*.xcconfig`, and a loader in `web/index.html` that starts Go and waits for `globalThis.fluffyReady` (called by `Serve`) before injecting `flutter_bootstrap.js`, showing an error in the page if Go fails. Each hook checks for `fluffy` first and fails with the shared `notFound` message instead of an opaque build error. Every text change sits between `fluffy:begin`/`fluffy:end` markers so re-applying is idempotent.
- `--patch-gtk` (`create`/`init`/`update`) is an opt-in hook that inserts a marked block before `if (use_header_bar) {` in `linux/runner/my_application.cc`, limiting the GTK header bar to GNOME (`XDG_CURRENT_DESKTOP`) so e.g. KDE draws its own server-side decoration. `hooks()` adds it with the flag or when the file already has the marker, so `update` keeps it.
- `testdata/` holds pbxproj/index.html/my_application.cc files from a real `flutter create`; refresh them when Flutter's templates change.
